# dict/AGENTS.md — Dictionary Data Agent

This directory contains all dictionary data files used by Nazeka. The `dictionary-data` agent is responsible for maintaining these files.

## File Inventory

| File | Description | Generated? |
|------|-------------|------------|
| `JMdict1.json` ... `JMdict11.json` | JMdict dictionary split into chunks | Yes (gitignored) |
| `deconjugator.json` | Japanese deconjugation grammar rules | No (hand-maintained) |
| `kanjidata.json` | Individual kanji character data | No |
| `priority.json` | Word priority/ranking data | No |
| `freqlist_narou.json` | Frequency list from web novels (Narou) | Generated via `etc/process freqlist.py` |
| `freqlist_novels.json` | Frequency list from novels | Generated via `etc/process freqlist.py` |
| `freqlist_vns.json` | Frequency list from visual novels | Generated via `etc/process freqlist.py` |
| `jdic audio.txt` | Audio pronunciation lookup table | No |

## Critical Rules

### JMdict Files
- JMdict JSON files are **gitignored** — never commit them.
- They are generated by `etc/process.py` from `JMdict.gz` XML source.
- Currently split into 11 chunks for memory management.
- Every JMdict JSON file must be listed in `manifest.json` under `web_accessible_resources`.
- If a new split file is added (e.g., `JMdict12.json`), coordinate with `extension-config` agent to update the manifest.

### Deconjugation Rules
- `deconjugator.json` contains grammar rules for the deconjugation engine.
- Rules are applied iteratively with loop detection in `background-script.js`.
- After modifying rules, verify against `deconjugator checklist.txt` in the project root.
- Rule changes affect the `core-engine` agent's deconjugation logic.

### Frequency Lists
- Three separate frequency corpora provide different ranking signals.
- The `core-engine` agent uses these for result sorting heuristics.
- Changes to frequency list format require coordinated updates in `background-script.js`.

### Data Format
- All JSON files use standard JSON format (no comments, no trailing commas).
- Dictionary entries follow JMdict's XML schema converted to JSON objects.
- Kanji data and priority data have their own schemas used by `background-script.js`.
